Пару месяцев назад меня спросили: «Есть ли в Thunder Engine Gameplay Tags, как в Unreal Engine?» Я раньше не слышал о такой функции. Решил разобраться, что это за зверь, и заодно посмотрел, как это устроено в Unity и Godot. Так началось путешествие к системе тегов и групп — о которой я расскажу в этой статье.

## Что такое Gameplay Tags в Unreal Engine

Если не в курсе — это иерархические теги, которые можно назначить любому компоненту. Они помогают быстро проверить, принадлежит ли компонент определённой группе.

Проще говоря: с тегом Effect.Poison на компоненте можно быстро проверить:

- Есть ли у компонента вообще какой-нибудь Effect?
- Или конкретно — стоит ли на нём эффект Poison?

Выглядит удобно (хотя у меня есть сомнения насчёт использования тегов в их Ability System).

## А как в других движках

- **Unity** — есть система тегов, но она менее функциональна
- **Godot** — пошли другим путём: у них есть группы и метаданные

Сначала я посмотрел на метаданные. И тут до меня дошло: это по сути эквивалент моих динамических свойств!

## Динамические свойства в Thunder Engine (уже есть)

В Thunder Engine можно назначить любое свойство любому компоненту или актору, даже если у объекта такого свойства нет. Это делается через setProperty(name, value), где value может быть практически любого типа.

Получить значение обратно можно через property(name) — объект возвращает значение типа Variant, которое можно преобразовать в нужный тип:
cpp

property("health").toInt()

Я постоянно использую динамические свойства. Но групп у меня всё ещё не было.

## Теперь разберёмся с группами

Иерархию тегов я пока отложил — они будут плоскими. Вызов методов из группы — тоже пока не планирую.

### Зачем нужны группы прямо сейчас

Для более удобного управления компонентами внутри систем. Например:

- Чтобы строить карты теней, нужно быстро отфильтровать все источники света
- Или вызывать методы для симуляции игровой логики

Применений сотни.

## Новый API

Теперь у компонента есть два метода:
cpp

/*!
    Добавляет \a tag для текущего компонента.
    Автоматически добавляет компонент в конкретную группу Scene.
*/
void Component::addTag(const TString &tag)

/*!
    Удаляет \a tag для текущего компонента.
    Автоматически удаляет компонент из конкретной группы Scene.
*/
void Component::removeTag(const TString &tag)

А в Scene есть методы для работы с группами по строкам и по хешам:
cpp

void Scene::addToGroup(Object *object, const TString &group)
void Scene::addToGroupByHash(Object *object, uint32_t hash)

void Scene::removeFromGroup(Object *object, const TString &group)
void Scene::removeFromGroupByHash(Object *object, uint32_t hash)

Object::ObjectList &Scene::getObjectsInGroup(const TString &group)
Object::ObjectList &Scene::getObjectsInGroupByHash(uint32_t hash)

## Как это работает под капотом

- addTag("Enemy") автоматически добавляет компонент в группу "Enemy" в Scene
- removeTag("Enemy") — удаляет его из группы
- Внутри группы хранятся по хешам строк (хеширование через Mathf::hashString) для быстрого доступа
- Все операции потокобезопасны (есть мьютекс)

Всё просто, гибко и не привязано к каким-либо конкретным системам. Раньше приходилось копать в коде системы и добавлять группу вручную. Теперь достаточно одного тега!
